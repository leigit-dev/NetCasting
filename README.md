# NetCasting

**低延迟、纯 Python 驱动的局域网无损屏幕串流工具**

NetCasting 是一套专为局域网（LAN）环境设计的轻量级屏幕共享/串流软件。采用纯 Python 构建，无独立显卡要求，即可实现 1080p 60FPS 的无损画面传输与绝对同步的鼠标跟随。

## 核心特性

- **极速响应**：基于 Windows 原生 DXGI (Desktop Duplication API) 捕获屏幕，CPU 占用极低。
- **无损压缩**：摒弃传统的 H.264 视频编码（高延迟/画质损失），采用 LZ4 极速无损压缩，只传输发生变化的局部像素块。
- **鼠标独立通道**：视频流与鼠标流彻底分离。画面按 60fps 发送，鼠标坐标以 125Hz 独立 UDP 通道发送，B 端本地硬件级渲染。真正做到“指哪打哪”，丝滑跟手。
- **完美兼容虚拟显示器**：针对 Parsec VDD 等虚拟显卡做了专门适配，支持多屏幕、分辨率动态扩展。
- **断线重连与半路接入**：采用“动态边界扩张拼图”算法，即使 B 端在中途启动，也能自动扩容画布，完美拼接，拒绝黑屏死锁。
- **纯 CPU 运算**：无需独立显卡，轻薄本、办公机即可充当串流主机。

## 构建环境与依赖

- **操作系统**：Windows 10 / 11（仅限 Windows）
- **网络环境**：**千兆有线局域网（推荐，由于涉及高清流传输）**。不支持跨公网（互联网）使用。
- **Python 版本**：Python 3.9 及以上（推荐 3.10+）
- 建议使用`pygame-ce`代替pygame，兼容性更好

**安装依赖：**
```bash
pip install dxcam opencv-python numpy lz4 pygame pywin32 Pillow screeninfo
```

## 快速开始

### 1. 启动接收端
在需要看画面的设备上运行Receiver.exe
> 启动后，屏幕会显示一块深灰色的待机界面，并列出本机所有的局域网 IP 地址。

### 2. 启动发送端在需要被串流的设备上运行Sender.exe
> 1. 输入 B 端界面上显示的 IP 地址。
> 2. 在“选择要共享的屏幕”下拉框中，选择你要串流的屏幕。
> 3. 点击 **“▶ 开始串流”**。

## 打包为独立 EXE

本项目使用 `PyInstaller` 打包。

**打包接收端 (B端)：**
```bash
pyinstaller -F -w -i icon.ico --add-data "ibeam.png;." --hidden-import pygame receiver.py
```

**打包发送端 (A端) + 资源：**
```bash
pyinstaller -F -w -i icon.ico --add-data "logo.png;." --add-data "ibeam.png;." --hidden-import pystray --hidden-import PIL.ImageDraw --hidden-import screeninfo --hidden-import dxcam sender.py
```
> *注：请确保 `ibeam.png`（工字型光标素材）与脚本在同一目录，打包时会自动打入内部。*

## 工作原理 (架构解析)

1. **捕获 (A端)**：`dxcam` 按需捕获桌面帧，利用 `OpenCV` 计算帧间差异，算出发生变化的“最小外接矩形”。
2. **压缩 (A端)**：将矩形区域裁剪出来，使用 `lz4.block` 进行极速无损压缩（速率 > 500MB/s）。
3. **传输 (UDP)**：压缩后的数据被拆分为不超过 1472 字节的安全 UDP 小包，通过后台线程发送，避免阻塞主循环。同时独立线程高频发送鼠标坐标。
4. **渲染 (B端)**：使用 `Pygame`。背景画布仅更新变化的区域块（动态扩容机制）。鼠标图片由 A 端按需推送，B 端缓存并实时绘制，享受显卡级的平滑度。

## 常见问题排查 (FAQ)

**Q1: 提示 `COMError: (-2005270494)` 或无法识别虚拟屏怎么办？**
A: 这是因为虚拟显卡底层资源被锁死。请在任务管理器“服务”中，找到并重启虚拟显示器相关服务，或者直接在设备管理器中禁用再启用虚拟显示器。

**Q2: 接收端画面黑屏或丢包严重？**
A: 
1. 确认两端都在同一局域网，且没有开启 VPN 或网络代理。
2. 检查 Windows 防火墙，确保 Python 允许通过“专用网络”通信。
3. 串流非常依赖稳定的局域网带宽，尽量使用有线连接。

**Q3: 鼠标移动卡顿或有延迟？**
A: 请确保没有其他程序大量抢占 CPU。如果配置较低，可以适当调节Sender端的刷新率限制（默认无限制）。

**Q4: 能否跨公网使用？**
A: **绝对不能。** 本软件基于 UDP 开发，且没有做任何加密和公网穿透，跨公网会因为 ISP 限制导致严重的丢包和花屏。**请勿将本程序暴露在公网环境。**
